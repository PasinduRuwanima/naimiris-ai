# Chatbot design — planned

The chatbot and retrieval pipeline are not implemented in Phase 1. No provider
is contacted and no agricultural answer is generated by the foundation app.

Planned flow: question → language routing (English/Sinhala) → approved document
retrieval → relevance/coverage gate → bounded server-side generation → cited
answer. Unsupported questions must receive a clear evidence limitation. A
retrieval score is not proof that a source supports a claim.

Store title, publisher, URL, publication date when available, retrieval date,
language, topic, version, review status, and document/chunk IDs. Return references
that support the actual answer. Preserve Sinhala Unicode end to end. Evaluate
Sinhala retrieval and generation separately with reviewed questions.

Treat source documents and user input as untrusted data. They cannot override
system instructions. Keep LLM keys server-side, bound input/output lengths,
timeouts, and retrieval size, and do not log sensitive conversation content.

History will initially be in memory. Optional persistence needs consent,
retention, deletion, and authorization controls before implementation. Future
prediction context must retain model uncertainty and cannot become a confirmed
diagnosis. Expert referral is appropriate when evidence is insufficient.
